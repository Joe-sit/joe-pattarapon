## 2. What this session built (all in `stash@{0}`, on `react`)

- **`src/sections/mascot/MascotExport.tsx`** — a DEV-only `export glb` button,
  bottom-right of `/mascot`. `GLTFExporter` with `{ binary: true }` → Blob →
  anchor download. Verified end to end in headless Chromium: 96 KB out, 39
  meshes / 39 materials / 91 nodes, colours intact.
- **`Mascot.tsx`** gained a `rootRef` prop; the unused internal `root` ref it had
  was removed. `MascotScene` holds the ref outside the Canvas and threads it
  through `Rig` → `Mascot`, because the button is DOM and the figure is scene.

### Three things that bit, in order

1. **The button was invisible to clicks at `top-12`.** The site's `<nav>` is
   `fixed … z-50` and swallows pointer events across the whole top strip.
   Playwright said it plainly: `<nav …> intercepts pointer events`. Moved to
   `bottom-6 right-6`, clear of the nav above and of the furniture panel
   (`top-24`, grows downwards as it opens).
2. **Exporting the live group writes the framing offset into the file.** The
   figure sits inside `position={[0, FRAME_Y, 0]}`, which exists for the camera
   and for nothing else, and an exporter walks parents — so the model lands a
   metre in the air in Blender. Export `node.clone(true)` instead: no parent, so
   it writes at the origin, and geometry/materials are shared by reference so
   the copy is cheap.
3. **`GLTFExporter.parse` is asynchronous.** Its traversal runs *after* the
   calling function returns. The first attempt borrowed the live subtree onto a
   bare parent and put it back in a `finally` — which put it back before the
   exporter had walked it. The clone solves this too. (A separate red herring:
   revoking the object URL on the line after `link.click()` cancels the download
   in Chromium — it is now revoked on a `setTimeout(…, 0)`.)

### Known, accepted

`GLTFExporter: Use MeshStandardMaterial or MeshBasicMaterial for best results.`
— printed once per material. The whole figure is `meshLambertMaterial`; glTF has
no Lambert, so it is written as PBR with `metallic 0 / roughness 1`. Colours
survive exactly (`baseColorFactor` in linear space, correct). The model will
look less flat in Blender than it does on the page. Not a bug to chase.

## 5. Lessons from building the figure that are still true

These cost several rounds each and are cheap to lose.

- **Derive numbers from the body, never eyeball them.** `DESK.top` is computed
  from where the wrist lands after the whole arm chain is folded — so the hands
  sit on the desk by construction rather than by tuning. When a number *cannot*
  be derived (anything inside a bought GLB), give it a slider instead of a guess:
  that is what `FurnitureDebug.tsx` is, and it turned three edit-reload rounds
  per guess into one drag.
- **A joint on a blocky figure is a change of section, not a bend in a surface**
  — except at the *outside* of a fold, which is a barrel on the hinge axis.
  Cutting each piece's own back cannot work: with a 75° fold the two backs are
  75° apart and never meet as one curve.
- **Wind your triangles.** A fan wound inward is backface-culled and reads as a
  hole in the model — this presented as "ศอกนอกแหว่ง" and looked like a geometry
  bug.
- **`Box3.setFromObject` walks world matrices.** Measuring a mounted, scaled
  clone feeds its own output back in, and the sliders appear to "move at random".
  Measure the cached, unmounted `scene` from `useGLTF` instead — and clone before
  mutating anything, because drei caches the scene graph and a mutation leaks
  into every other use of that file.
- **`useProgress().active` is not a done signal.** It goes false in the gaps
  between requests, so a three-file scene opens the gate early. What is
  unambiguous is React: a component *inside* the `<Suspense>` boundary cannot
  render until every promise in it resolves. That is `<AssetsMounted />`.
- Shadows and `dpr={[1,2]}` are **off on purpose** while the shape is being
  argued about — they were paying for finish while every decision is read off a
  screenshot. The values to restore are in the comment in `MascotScene.tsx`.
